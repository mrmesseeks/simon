# SEQ-ORD-005 - Альтернативная онлайн-оплата - Podeli / OTP

**Назначение**

Альтернативный AS-IS сценарий онлайн-оплаты уже созданного заказа через сервисы Podeli или OTP «Давай делить». Сценарий заменяет в `SEQ-ORD-001` только стандартный участок оплаты через RBS / Альфа-Банк. После успешного подтверждения платежа OpenCart переводит заказ в состояние «Оплачен», после чего заказ возвращается в основной жизненный цикл.

**Начальная точка**

В OpenCart уже создан Order, для которого выбран способ оплаты Podeli либо OTP «Давай делить».

**Основные условия сценария**

* Podeli и OTP являются альтернативами стандартной онлайн-оплате через RBS;

* для Podeli OpenCart создаёт платёжный заказ во внешнем сервисе и перенаправляет клиента на полученный URL оплаты;

* для OTP OpenCart формирует переход клиента в форму «Давай делить» с идентификатором заказа и составом товаров;

* успешный callback Podeli имеет состояние `COMPLETED`, успешный callback OTP — `COMPLETE`;

* при успешном callback OpenCart переводит Order в состояние «Оплачен»;

* Podeli может предварительно прислать `WAIT_FOR_COMMIT`; OpenCart переводит заказ в ожидание оплаты и автоматически подтверждает платёж в Podeli;

* после успешной оплаты OpenCart выполняет фискализацию через ATOL;

* технические endpoint, payload, callback URL и внутренние записи `order_rbs` в бизнес-диаграмме не раскрываются;

* фактическая частота / использование обоих способов оплаты в текущем production отдельно не подтверждены.

**Основной путь**

1. Клиент выбирает Podeli либо OTP «Давай делить» для оплаты существующего заказа.

2. OpenCart инициирует соответствующий внешний платёжный сценарий и переводит клиента в интерфейс платёжного сервиса.

3. Клиент оформляет оплату / рассрочку во внешнем сервисе.

4. Платёжный сервис сообщает OpenCart состояние операции.

5. Для Podeli при промежуточном состоянии ожидания подтверждения OpenCart подтверждает платёж в Podeli и ожидает финальный результат.

6. После финального успешного статуса OpenCart переводит заказ в состояние «Оплачен».

7. OpenCart формирует фискальный чек через ATOL.

8. Изменение состояния заказа синхронизируется с связанными системами стандартными механизмами OpenCart.

9. Сценарий возвращается в `SEQ-ORD-001` на участок обработки уже оплаченного заказа — проверка сделки в AmoCRM и последующая передача в бухгалтерский контур.

**Граница сценария**

`SEQ-ORD-005` заменяет в `SEQ-ORD-001` только стандартную оплату через RBS. Создание заказа до начала оплаты и дальнейшая обработка после состояния «Оплачен» остаются частью основного жизненного цикла.

Возвраты после ранее успешной оплаты относятся к `SEQ-ORD-008` и в этой диаграмме подробно не раскрываются.

**Особенности**

* Podeli: `COMPLETED` переводит Order в «Оплачен»; `WAIT_FOR_COMMIT` переводит его в «В ожидании оплаты» и запускает автоматическое подтверждение; `REJECTED` и `REFUNDED` в текущем коде возвращают заказ в состояние «В обработке».

* OTP: `COMPLETE` переводит Order в «Оплачен» только при совпадении суммы и допустимом текущем состоянии заказа; `REFUND` переводит заказ в состояние отмены.

* Для обоих успешных сценариев фискальный чек формируется через ATOL.

* Эти различия важны для AS-IS, но в основной sequence показан общий бизнес-результат успешной оплаты, а возвраты вынесены в отдельный сценарий.

@startuml
title SEQ-ORD-005 Альтернативная онлайн-оплата — Podeli / OTP - AS-IS

autonumber

actor "Клиент" as Client
participant "OpenCart" as OC
participant "Podeli" as Podeli
participant "OTP\nДавай делить" as OTP
participant "ATOL" as Atol
participant "AmoCRM" as Amo
participant "Bitrix" as Bitrix

== Выбор альтернативной оплаты ==

Client -> OC : Выбрать способ оплаты\nPodeli или OTP

alt Podeli
    OC -> Podeli : Создать платёжный заказ
    Podeli --> OC : Вернуть redirectUrl
    OC --> Client : Перенаправить в Podeli
    Client -> Podeli : Оформить оплату / рассрочку

    opt WAIT_FOR_COMMIT
        Podeli -> OC : Callback\nWAIT_FOR_COMMIT
        OC -> OC : Перевести Order\nв «В ожидании оплаты»
        OC -> Podeli : Подтвердить платёж\ncommit
        Podeli --> OC : Результат подтверждения
    end

    Podeli -> OC : Callback\nCOMPLETED
    OC -> OC : Перевести Order\nв «Оплачен»
    OC -> Atol : Сформировать фискальный чек
    Atol --> OC : Результат фискализации

    par AmoCRM
        OC -> Amo : Синхронизировать\nсостояние «Оплачен»
    else Bitrix
        OC -> Bitrix : Синхронизировать\nсостояние заказа
    end

else OTP «Давай делить»
    OC --> Client : Перенаправить в форму\n«Давай делить»
    Client -> OTP : Оформить оплату / рассрочку
    OTP -> OC : Callback COMPLETE\nс суммой заказа
    OC -> OC : Проверить сумму и\nдопустимое состояние Order

    alt Проверка пройдена
        OC -> OC : Перевести Order\nв «Оплачен»
        OC -> Atol : Сформировать фискальный чек
        Atol --> OC : Результат фискализации

        par AmoCRM
            OC -> Amo : Синхронизировать\nсостояние «Оплачен»
        else Bitrix
            OC -> Bitrix : Синхронизировать\nсостояние заказа
        end
    else Проверка не пройдена
        OC -> OC : Не изменять состояние Order
    end
end

note over Client,Bitrix
Заменяет RBS-ветку SEQ-ORD-001.
После «Оплачен» — возврат в основной lifecycle.
end note
