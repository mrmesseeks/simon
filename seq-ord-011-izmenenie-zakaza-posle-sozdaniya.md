# SEQ-ORD-011 - Изменение заказа после создания

**Назначение**

AS-IS сценарий изменения уже созданного заказа после его первичной регистрации. Сценарий объединяет два подтверждённых направления: изменение заказа менеджером в OpenCart Admin с последующей синхронизацией в AmoCRM и изменение реквизитов сделки в AmoCRM с обратным обновлением Order OpenCart. Для изменений, которые должны быть известны 1С, используются отдельные события `change_order`, `change_product` и, при возврате сделки назад из бухгалтерского участка, `back_status`.

**Начальная точка**

Заказ уже существует в OpenCart и связан со сделкой AmoCRM.

**Основные условия сценария**

* изменение выполняется после создания заказа;

* при изменении Order в OpenCart актуальные данные сделки обновляются в AmoCRM — `ORD-004`;

* если в OpenCart изменился состав товаров, код сравнивает текущий состав с ранее сохранённым составом сделки; при изменении и нахождении сделки на статусе, разрешённом для обмена с 1С, формируется `change_product` — `ORD-008`;

* изменения сделки AmoCRM поступают в OpenCart через `leads.update` / webhook-контур — `ORD-005`;

* OpenCart сравнивает значения AmoCRM с текущими данными Order и обновляет только реально изменившиеся реквизиты;

* если изменены реквизиты заказа и текущий статус AmoCRM разрешает обмен с 1С, формируется `change_order` с перечнем изменённых полей — `ORD-007`;

* если сделка возвращается с этапа, относящегося к передаче в 1С, на один из обратных этапов, формируется `back_status` — `ORD-009`;

* изменение статуса обрабатывается отдельно от изменения реквизитов: OpenCart синхронизирует статус Order с состоянием сделки;

* конкретная внутренняя обработка событий `change_order`, `change_product` и `back_status` в 1С в доступных источниках не раскрыта.

**Основной путь**

1. Изменение существующего заказа может начаться либо в OpenCart Admin, либо в AmoCRM.

2. При изменении в OpenCart данные Order сохраняются и связанная сделка AmoCRM актуализируется.

3. Если изменился состав товаров, OpenCart формирует `change_product` и передаёт событие в 1С при выполнении статусного условия.

4. При изменении сделки в AmoCRM webhook передаёт обновление в OpenCart.

5. OpenCart определяет изменённые поля, обновляет соответствующие реквизиты Order и при необходимости состояние заказа.

6. Если обнаружены изменения реквизитов и статус сделки разрешает обмен с 1С, OpenCart передаёт `change_order` с перечнем изменённых реквизитов.

7. Если изменение является возвратом сделки назад из бухгалтерского этапа, OpenCart дополнительно формирует `back_status`.

8. Изменения OpenCart, попадающие в стандартный контур синхронизации заказа, передаются в Bitrix как обновление заказа.

**Результат выполнения**

Данные существующего заказа синхронизированы между OpenCart и AmoCRM. При изменениях, влияющих на уже переданный в 1С заказ, 1С получает соответствующее событие об изменении реквизитов, состава или возврате статуса.

**Особенности**

* `change_order` передаёт не старые и новые значения, а перечень изменённых реквизитов в `change_data`.

* `change_product` формируется только при фактическом изменении состава товаров, определяемом сравнением текущего состава с сохранённым состоянием сделки.

* изменение способа доставки / оплаты нормализуется для 1С до значений `shipping` / `payment`; технические ключи `shipping_method` / `payment_method` из списка изменений удаляются.

* изменение склада формирует дополнительный комментарий в AmoCRM.

* webhook AmoCRM обрабатывается асинхронно через Redis; детали очереди не показаны на диаграмме, чтобы сохранить бизнесовый уровень сценария.
