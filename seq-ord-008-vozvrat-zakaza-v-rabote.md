# SEQ-ORD-008 - Возврат заказа - в работе

**Назначение**

Отдельный AS-IS сценарий обработки возврата существующего заказа. Состояние возврата ведётся в отдельной воронке AmoCRM, изменения сделки через стандартный webhook-контур доходят до OpenCart, после чего OpenCart синхронизирует состояние Order и передаёт в 1С одно из событий `refund`, `refund_full` или `refund_processed` (`ORD-039`).

**Начальная точка**

Возврат инициирует менеджер в AmoCRM: он переводит сделку в возврат либо полный возврат.

**Основные условия сценария**

* `Возврат` / `Возврат полный` — решение принимает менеджер в AmoCRM;

* изменение из AmoCRM через стандартный webhook-контур поступает в OpenCart, после чего OpenCart синхронизирует Order и уведомляет 1С событиями `refund` / `refund_full`;

* после фактического получения возвращённого заказа складом состояние `Возврат обработан` формируется **со стороны 1С**;

* таким образом, `Возврат обработан` не следует моделировать как очередной ручной переход менеджера AmoCRM;

* для продажи с сайта в `1С:УНФ` при возврате создаётся документ **«Корректировка расходной накладной»**;

* для офлайн-продажи магазина в `1С:УНФ` создаётся **«Чек ККМ на возврат»**; этот офлайн-сценарий не является возвратом Order сайта.

**Технические факты**

* воронка возврата AmoCRM: `pipeline_id = 2031355`;

* в коде обрабатываются статусы `Возврат: В работе` (`29725438`), `Возврат: Полный возврат` (`84029357`) и `Возврат: возврат обработан` (`84029361`);

* изменения AmoCRM поступают через `leads.update` / `amo_webhook`;

* для направления OpenCart → 1С используются события `refund` и `refund_full` через `sendOrderInfoIn1c`;

* `back_status` не относится к товарному возврату: это отдельный сценарий возврата сделки назад из бухгалтерского этапа основной воронки.

**Основной путь**

1. Менеджер AmoCRM принимает решение о возврате.

2. Менеджер переводит сделку в `Возврат` либо `Возврат полный`.

3. AmoCRM отправляет изменение сделки в OpenCart через webhook.

4. OpenCart обновляет состояние связанного Order.

5. OpenCart уведомляет 1С: `refund` для возврата либо `refund_full` для полного возврата.

6. В `1С:УНФ` для продажи с сайта оформляется документ «Корректировка расходной накладной».

7. Возвращённый заказ фактически поступает на склад.

8. После получения заказа складом 1С становится источником состояния `Возврат обработан` и меняет статус возврата со своей стороны.

9. Остальные системы должны получить итоговое состояние через действующий контур статусной синхронизации 1С / OpenCart / AmoCRM; конкретный технический вызов именно для этого перехода в предоставленном ответе не указан.

== Инициация возврата ==

Manager -> Amo : Перевести сделку\nв «Возврат» / «Полный возврат»
Amo -> Redis : leads.update
Redis -> OC : Обработать amo_webhook

alt Возврат
    OC -> OC : Обновить Order\n«Возврат»
    OC -> OneC : refund
else Полный возврат
    OC -> OC : Обновить Order\n«Возврат полный»
    OC -> OneC : refund_full
end

OneC -> OneC : Создать / обработать\n«Корректировку расходной накладной»\nдля продажи с сайта

== Завершение возврата ==

Warehouse -> OneC : Возвращённый заказ\nполучен складом
OneC -> OneC : Установить состояние\n«Возврат обработан»

note over OneC,Amo
Источник финального состояния
«Возврат обработан»- 1С.
Дальнейшая синхронизация состояния
идёт из контура 1С в остальные системы.
end note
