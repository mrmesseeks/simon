# SEQ-ORD-004 - Регистрация чека / продажи магазина из 1С в AmoCRM4 - не используется на production

{red}(P.S не используется на production)

**Назначение**

Отдельный AS-IS сценарий передачи данных из 1С через интеграционный контур OpenCart в AmoCRM. По ответу разработчика `creatingOrderFrom1c` используется для отправки чеков; текущая реализация создаёт по полученным данным сделку в воронке AmoCRM «Магазины». Точный бизнес-объект и событие в 1С, которые формируют этот вызов, отдельно не подтверждены.

**Начальная точка**

В 1С сформированы данные чека / продажи магазина, которые необходимо зарегистрировать в AmoCRM.

**Основные условия сценария**

* источник данных - 1С;

* для передачи используется `creatingOrderFrom1c`;

* OpenCart в этом сценарии выступает интеграционным посредником и не создаёт новый Order в своей базе;

* обязательным для обработки является номер заказа / операции 1С `number1c`;

* в AmoCRM создаётся новая сделка в воронке «Магазины»;

* к сделке передаются сумма, подразделение / город, номер в 1С, данные клиента, товары и комментарий;

* если контакт AmoCRM уже известен, он связывается со сделкой; при отсутствии контакта обработчик может создать контакт по данным клиента;

* сценарий не подтверждён как точка входа в стандартный розничный lifecycle `SEQ-ORD-001`.

**Основной путь**

1. 1С формирует данные чека / продажи магазина.

2. 1С передаёт данные в интеграционный контур OpenCart.

3. OpenCart подготавливает данные сделки для воронки AmoCRM «Магазины».

4. OpenCart связывает существующий контакт AmoCRM либо формирует данные нового контакта при необходимости.

5. OpenCart создаёт сделку в AmoCRM с суммой продажи, источником / городом и номером операции в 1С.

6. В сделку добавляются сведения о товарах и комментарий, полученные из 1С.

7. OpenCart возвращает результат обработки стороне 1С.

**Граница сценария**

`SEQ-ORD-004` не является альтернативой созданию розничного Order клиентом, менеджером или Bitrix. Текущий код `creatingOrderFrom1c` не создаёт Order OpenCart: OpenCart используется как интеграционный слой для создания сделки AmoCRM в отдельной воронке «Магазины».

Поэтому переход из этого сценария в `SEQ-ORD-001` не фиксируется.

**Особенности**

* техническая точка входа: `extension/module/1ctoamo/creatingOrderFrom1c`;

* в текущем коде используется `pipeline_id = 6970626` - воронка «Магазины»;

* при ошибке создания сделки запрос помещается в очередь повторной обработки `creatingOrderFrom1c` / `creatingOrderFrom1c_2`;

* ответ разработчика подтверждает использование endpoint «для отправки чеков», но не раскрывает, какое именно событие 1С инициирует вызов и является ли `number1c` номером чека, заказа магазина или другого документа. Это остаётся границей подтверждённой бизнес-семантики.
