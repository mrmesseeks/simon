# SEQ-ORD-010 - Оформление, комплектация и доставка заказа

**Назначение**

Детализация стандартного AS-IS участка розничного заказа после завершения бухгалтерской обработки в 1С: оформление отправления, комплектация и дальнейшая доставка до получения заказа клиентом. Сценарий является продолжением участка `SEQ-ORD-009` и раскрывает различия между внешней транспортной компанией, собственным курьером Angiopharm и самовывозом.

**Начальная точка**

Заказ завершил бухгалтерскую обработку и находится на этапе «На оформлении в ТК».

**Основные условия сценария**

* источник истины по оформлению отправления и состояниям доставки в текущем AS-IS - 1С; встроенный экспорт заказов и импорт статусов APIShip в OpenCart в продуктивном контуре не используются;

* для внешней транспортной компании 1С создаёт отправление через APIShip; прямые обращения 1С к CDEK / Яндекс.Доставке / Почте России используются для обогащения данных, необходимых для печати этикеток;

* движение заказа по этапам комплектации в 1С инициирует передачу новых состояний в OpenCart через `changeStatusBatch`;

* для внешней доставки webhook APIShip принимается в 1С; после него 1С передаёт в OpenCart состояние заказа через `changeStatusBatch` и, при необходимости, трек-номер через `setTrackNumber` - `ORD-010`;

* для розничного заказа подтверждены состояния доставки «В пути», «Ожидает в пункте выдачи» и «Получен и подтверждён»;

* для собственного курьера используется отдельный контур 1С ↔ Яндекс Маршрутизация ↔ AmoCRM; он не связан с webhook APIShip и `setTrackNumber`;

* точная последовательность статусов OpenCart / AmoCRM для самовывоза в доступных источниках не подтверждена.

**Основной путь**

 1. После перехода заказа на этап «На оформлении в ТК» 1С начинает оформление доставки.

 2. Для внешней ТК 1С создаёт отправление через APIShip и при необходимости запрашивает дополнительные данные непосредственно у перевозчика для подготовки этикетки.

 3. По мере прохождения складских этапов 1С передаёт состояния заказа в OpenCart. Для некурьерской ветки подтверждена последовательность `33 - Готов к сборке` → `5 - В сборке` → `15 - Собран, готов к отгрузке`. Курьерские заказы минуют этап `33` и сразу переходят в `5 - В сборке`.

 4. Состояние `5 - В сборке` соответствует началу работы ТСД. После завершения сборки заказ переходит в `15 - Собран, готов к отгрузке`; этот этап также используется как очередь собранных заказов, ожидающих даты доставки, и для заказа после неуспешной попытки передачи курьером.

 5. OpenCart сохраняет новое состояние Order; дальнейшая синхронизация заказа выполняется штатными механизмами интеграций OpenCart.

 6. При изменении состояния внешней доставки APIShip отправляет webhook в 1С.

 7. 1С передаёт в OpenCart соответствующее состояние заказа через `changeStatusBatch` и трек-номер через `setTrackNumber`, если он получен или изменён.

 8. `setTrackNumber` сохраняет трек в OpenCart и передаёт его в AmoCRM; изменение Order также попадает в общий контур синхронизации заказа.

 9. Для собственного курьера данные маршрута обрабатываются в 1С через Яндекс Маршрутизацию, а ссылка передаётся напрямую в AmoCRM при начале работы курьера с маршрутом, итоговое состояние - при завершении заказа. Точное техническое событие Яндекс Маршрутизации для этих переходов не подтверждено.

10. Самовывоз показан отдельной веткой без детализации неподтверждённых статусных переходов.

**Результат выполнения**

Для внешней ТК заказ получает актуальные данные отправления, проходит комплектацию и по состояниям доставки доходит до «Получен и подтверждён». Для собственного курьера завершение доставки отражается через прямую интеграцию 1С → AmoCRM. Технический статусный путь самовывоза требует отдельного подтверждения.

**Особенности**

* Наличие кода полного цикла APIShip в OpenCart не означает его использование: регистрация отправлений, импорт статусов по cron и очередь `apiship_status` в текущем продуктивном процессе не используются.

* `changeStatusBatch` изменяет Order OpenCart через стандартный `addOrderHistory`; отдельный `ORD-*` для этого endpoint в реестре не подтверждён.

* `ORD-010` относится к `setTrackNumber`, а не ко всем изменениям состояния доставки.

* В `setTrackNumber` автоматическая установка розничного статуса «В пути» закомментирована; состояние доставки приходит отдельным вызовом из 1С.

**Подтверждённые статусы AmoCRM на участке доставки**

* `status_id = 45651853` - **«В пути»** воронки физических лиц. Для внешней доставки состояние Order передаётся из 1С отдельным `changeStatusBatch` (`statusId = 45`) после обработки webhook APIShip; трек-номер при необходимости передаётся отдельно через `setTrackNumber`. После изменения Order статус синхронизируется в AmoCRM.

* `status_id = 30636220` - **«Трэк отправлен, ждём оплату»** воронки дистрибьюторов. На этом этапе находятся сделки с предоплатой более 50%, но без полной оплаты; трек уже сформирован и заказ может быть отправлен клиенту. После поступления полной оплаты в 1С 1С отправляет webhook на сайт, сайт фиксирует факт полной оплаты, после чего роботы AmoCRM переводят сделку в успешный статус.

Эти два status ID относятся к разным воронкам и не должны трактоваться как один и тот же этап доставки.
