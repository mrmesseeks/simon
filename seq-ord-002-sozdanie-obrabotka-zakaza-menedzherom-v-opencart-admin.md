---
title: SEQ-ORD-002 - Создание / обработка заказа менеджером в OpenCart Admin
---

AS-IS сценарий создания или изменения заказа менеджером через административный интерфейс OpenCart. Диаграмма фиксирует отличие точки входа от клиентского сценария: менеджер работает с формой заказа в OpenCart Admin, после чего сохранение выполняется через Catalog API OpenCart. После создания или изменения Order синхронизируется с AmoCRM и Bitrix и далее входит в общий жизненный цикл заказа.

**Начальная точка**

Менеджер открывает в OpenCart Admin форму создания нового заказа либо редактирования существующего.

**Основные условия сценария**

- источник действия - менеджер в OpenCart Admin;
- создание выполняется через `api/order/add`, редактирование - через `api/order/edit`;
- Order сохраняется штатной моделью `ModelCheckoutOrder`, то есть используется тот же объект заказа OpenCart, что и в других сценариях;
- создание сделки AmoCRM после создания нового Order выполняется асинхронно через Redis `create_deal`;
- изменения существующего Order после сохранения передаются в связанную сделку AmoCRM через `updateDeal`, если интеграция Examo включена;
- создание и изменение Order попадают в Kafka-контур через CDC/outbox OpenCart;
- дальнейшая оплата, бухгалтерская обработка, комплектация и доставка не дублируются в этой диаграмме и относятся к общим сценариям жизненного цикла заказа.

**Основной путь**

1. Менеджер вводит или изменяет данные клиента, состав заказа, способ доставки, способ оплаты, комментарий и статус в форме заказа OpenCart Admin.
2. При создании нового заказа Admin вызывает Catalog API OpenCart `api/order/add`.
3. Catalog API формирует данные заказа и вызывает `ModelCheckoutOrder::addOrder()`.
4. OpenCart создаёт Order и добавляет начальную запись истории статуса.
5. После успешного создания API помещает в Redis очередь `create_deal` данные `order_id`, `admin_id` и выбранный склад `ship_warehouse`.
6. Worker OpenCart получает задачу `create_deal` и создаёт либо связывает сделку AmoCRM с созданным Order.
7. Создание заказа фиксируется CDC-механизмом OpenCart как событие `created`; событие формируется в outbox и публикуется в Kafka `prod.orders`, после чего его получает Bitrix.
8. При редактировании существующего заказа Admin вызывает Catalog API `api/order/edit` с `order_id`.
9. Если менеджер изменил статус, Catalog API перед сохранением вызывает `addOrderHistory()`.
10. Catalog API вызывает `ModelCheckoutOrder::editOrder()`, после чего OpenCart сохраняет актуальные реквизиты, товары, суммы, доставку и другие данные Order.
11. После фиксации изменения OpenCart обновляет связанную сделку AmoCRM через Examo `updateDeal`, если интеграция включена.
12. Изменения Order фиксируются CDC/outbox и передаются в Kafka как `updated` либо `status_changed` в зависимости от характера изменения; Bitrix синхронизирует заказ.
13. После создания или редактирования заказ продолжает обработку по соответствующему общему сценарию: оплате, передаче в бухгалтерский контур, комплектации и доставке.

| **Точка ветвления** | **Условие** | **Поведение** {width=326px} | **Тип** |
|---|---|---|---|
| Действие менеджера | Создаётся новый заказ | api/order/add -> addOrder() -> новый Order -> Redis create_deal -> AmoCRM; параллельно created -> Kafka -> Bitrix | alt |
| Действие менеджера | Редактируется существующий заказ | api/order/edit -> editOrder() -> обновление AmoCRM -> Kafka | alt |
| Редактирование заказа | Изменён статус | Перед сохранением вызывается addOrderHistory(); изменение статуса также участвует в синхронизации AmoCRM и Kafka | opt |
| Дальнейшая обработка | Заказ создан или изменён | Заказ продолжает общий lifecycle; переход в 1С и доставка выполняются только при наступлении соответствующих условий | Продолжение сценария |

**Особенности**

- OpenCart Admin не записывает заказ непосредственно в БД: форма вызывает Catalog API OpenCart.
- Для нового заказа создание сделки AmoCRM выполняется через очередь Redis `create_deal`; это отличается от обновления уже существующего заказа, где после сохранения вызывается Examo `updateDeal`.
- Kafka не вызывается напрямую из Admin-контроллера. События `created`, `updated` и `status_changed` формируются через CDC/outbox по факту изменений Order.
- Само редактирование заказа в Admin не означает автоматическую отправку `change_order` или `change_product` в 1С. Такие вызовы относятся к отдельным интеграционным условиям и дальнейшему жизненному циклу заказа.
- В кодовой базе существует отдельный AMO-режим оформления заказа менеджером через CRM. Он не включён в `SEQ-ORD-002`: текущая диаграмма описывает именно работу через OpenCart Admin.

```plant-uml
@startuml
title SEQ-ORD-002 Создание заказа менеджером в OpenCart Admin — AS-IS

autonumber

actor "Менеджер" as Manager
participant "OpenCart Admin" as Admin
participant "OpenCart\nCatalog API" as API
participant "OpenCart" as OC
queue "Redis" as Redis
participant "AmoCRM" as Amo
queue "Kafka\nprod.orders" as Kafka
participant "Bitrix" as Bitrix

== Формирование заказа ==

Manager -> Admin : Создать новый заказ
Manager -> Admin : Заполнить данные заказа\nКлиент, товары, количество,\nдоставка, оплата, склад,\nкомментарий, начальный статус
Manager -> Admin : Подтвердить создание

== Создание Order ==

Admin -> API : Передать данные нового заказа\nORD-002

note over Admin, API
  Технически используется: api/order/add
end note

API -> OC : Создать Order
OC -> OC : Сохранить данные заказа,\nтовары, суммы и доставку
OC -> OC : Зафиксировать\nначальное состояние заказа
OC -> API : Order создан\norder_id

== Регистрация заказа в AmoCRM ==

API -> Redis : Поставить задачу создания сделки\nORD-003

note over API, Redis
  В create_deal передаются:
  order_id, admin_id, ship_warehouse
end note

Redis -> OC : Обработать create_deal
OC -> Amo : Создать / связать\nсделку с Order
Amo -> OC : Результат обработки сделки

== Синхронизация с Bitrix ==

OC -> Kafka : Передать создание Order\nORD-012

note over OC, Kafka
  Событие created формируется
  через CDC / outbox OpenCart.
end note

Kafka -> Bitrix : Синхронизировать\nсозданный заказ

== Продолжение обработки ==

note over Manager, Bitrix
  SEQ-ORD-002 заменяет в SEQ-ORD-001 только
  стандартное создание заказа клиентом.

  После создания Order, регистрации сделки AmoCRM
  и синхронизации с Bitrix заказ продолжает
  общий жизненный цикл.

  Точка продолжения зависит от способа оплаты
  и начального состояния, заданных менеджером
  при создании заказа.
end note

@enduml
```
